# Kitchen Safety Violations — YOLO Dataset

Professional dataset layout for **YOLOv8** training, **Roboflow** export/import, and integration with the **Taeen Quality Platform** FastAPI monitoring pipeline (`analyze-frame` / `yolo_monitoring_service`).

## Directory layout

```
dataset/
├── helmet/              # Head protection present
├── mask/                # Face mask present
├── gloves/              # Gloves present
├── hairnet/             # Hairnet / head cover present
├── trash/               # Floor litter, bins, waste
├── dirty_surface/       # Contaminated prep surfaces, spills
├── improper_uniform/    # Non-compliant clothing
├── no_mask/             # Face mask explicitly absent (violation)
├── no_gloves/           # Gloves explicitly absent (violation)
├── no_hairnet/          # Hairnet explicitly absent (violation)
├── wet_floor/           # Wet / slippery floor hazard
├── yolo_export/         # Unified train/val split (generated by organize_dataset.py)
├── dataset.yaml         # Ultralytics YOLO config
└── README.md            # This file
```

Each class folder contains:

| Subfolder | Purpose |
|-----------|---------|
| `raw/` | Original images from cameras, Roboflow export, or manual collection |
| `labeled/` | YOLO `.txt` labels + images before train/val split (same basename) |
| `train/` | Training split → `images/` + `labels/` |
| `valid/` | Validation split → `images/` + `labels/` |

After running `scripts/organize_dataset.py`, the merged Ultralytics layout is written to **`yolo_export/`** (used by `dataset.yaml`).

## Class definitions

### Presence / safe-state classes (indices 0–6)

| ID | Folder | What to capture | Backend mapping (inference) |
|----|--------|-----------------|------------------------------|
| 0 | **helmet** | Worker wearing hard hat or chef toque; include positive (wearing) and negative (missing) in the same folder | `no_headcover` — absence inferred when score < threshold |
| 1 | **mask** | Face mask worn correctly; partial occlusion, side angles | complement to `no_mask`; together drive `no_mask` violation |
| 2 | **gloves** | Food-handling gloves on both hands | complement to `no_gloves`; together drive `no_gloves` violation |
| 3 | **hairnet** | Hairnet, snood, or approved head cover in prep zones | `no_headcover` — same violation type as helmet |
| 4 | **trash** | Items on floor, overflowing bins, bags near prep (not worn PPE) | `trash_on_floor`, `improper_waste_area` |
| 5 | **dirty_surface** | Stains, spills, unclean counters, open waste on work surfaces | `improper_waste_area` |
| 6 | **improper_uniform** | Missing apron/vest, street clothes in kitchen, wrong color PPE | `improper_uniform` |

### Explicit violation / absence classes (indices 7–10)

These are direct negative examples — the violation is unambiguously visible. Training with explicit absence classes improves recall on the missing-PPE detections that the positive classes can miss.

| ID | Folder | What to capture | Backend mapping (inference) |
|----|--------|-----------------|------------------------------|
| 7 | **no_mask** | Worker's face clearly visible with no mask at all — close-up and mid-range angles | `no_mask` violation — `_YOLO_CLASS_MAP`: `("mask", True)` |
| 8 | **no_gloves** | Bare hands during food prep or food contact; multiple angles | `no_gloves` violation — `_YOLO_CLASS_MAP`: `("glove", True)` |
| 9 | **no_hairnet** | Head clearly visible without any hairnet or cover in a prep zone | `no_headcover` violation — `_YOLO_CLASS_MAP`: `("helmet", True)` |
| 10 | **wet_floor** | Wet, slippery, or flooded floor surface; wet-floor warning signs also useful | **Pending** — new `wet_floor_hazard` violation type needed in Phase 3 backend update |

> **Note — `wet_floor` backend mapping:** The `_YOLO_CLASS_MAP` in `yolo_monitoring_service.py` does not yet contain a `wet_floor` entry. When Phase 3 training is complete, add `"wet_floor": ("wet_floor", True)` to the map and a corresponding `VIOLATION_METADATA` entry. Do not update the backend before the model is trained and validated.

## Labeling guidelines

1. Use **YOLO format**: one `.txt` per image, normalized `class_id x_center y_center width height` (0–1).
2. In per-class folders, use class id **`0`** in the `.txt` file (single-class collection). After merge, `organize_dataset.py` rewrites ids to the global index from `dataset.yaml`.
3. Prefer **bounding boxes** around the violation region (mask on face, gloves on hands, trash on floor).
4. For `no_mask`, `no_gloves`, `no_hairnet`: box tightly around the face/hands/head area — this teaches YOLO where to look, not just that the class exists.
5. Include varied lighting, camera heights (CCTV), and busy kitchens to match production.
6. Aim for **≥200 images per class** before serious training; balance positive/negative where applicable.
7. For absence classes (`no_mask`, `no_gloves`, `no_hairnet`): collect at least as many images as the corresponding presence class to avoid confidence imbalance.

## Workflow

### 1. Collect images

```bash
# Optional: fetch from Roboflow or URLs (see scripts/download_images.py)
export ROBOFLOW_API_KEY=your_key
python scripts/download_images.py --roboflow-project YOUR_PROJECT --roboflow-version 1 --class no_mask
```

Place files under `dataset/<class>/raw/images/` (or copy Roboflow export into `labeled/`).

### 2. Label (Roboflow or local)

- Export from [Roboflow](https://roboflow.com) as **YOLOv8** → copy into `dataset/<class>/labeled/images` and `labeled/labels`.
- Or label in Roboflow and download per-class into the matching folder.

### 3. Organize train/val + unified export

```bash
cd /path/to/ska-system
python scripts/organize_dataset.py --val-ratio 0.2 --seed 42
```

This fills per-class `train/` & `valid/` and builds `dataset/yolo_export/` for training.

### 4. Train YOLOv8 (local or Colab)

```bash
yolo detect train data=dataset/dataset.yaml model=yolov8n.pt epochs=100 imgsz=640
```

Copy the best weights to `backend/ml/models/` and set `YOLO_MODEL_PATH` (see `backend/ml/models/README.md`).

### 5. FastAPI / production

The backend loads weights via `yolo_model_resolver.py` and runs inference in `yolo_monitoring_service.py`. Class names in your trained model must match the **names** block in `dataset.yaml` for consistent reporting.

After training with `wet_floor`, add the backend mapping before deploying:
1. Add `"wet_floor": ("wet_floor", True)` to `_YOLO_CLASS_MAP` in `yolo_monitoring_service.py`
2. Add `_SCENE_ROUTING_KEYS` or a new check path depending on whether the violation is per-person or scene-level
3. Add a `VIOLATION_METADATA` entry with `severity`, `category`, and `suggested_action`
