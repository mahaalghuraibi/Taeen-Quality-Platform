## 1. دور المدير العام

المدير العام (Admin) مسؤول عن:

- **الإشراف الكلّي** على جميع الفروع والمستخدمين.
- **اعتماد الحسابات الجديدة** وترقية الأدوار.
- **مراقبة أداء النظام** وحالة الذكاء الاصطناعي.
- **إصدار التقارير العليا** للإدارة التنفيذية.
- **التواصل مع الدعم الفني** عند المشاكل التقنية.

> المدير العام ليس مسؤولًا عن التشغيل اليومي للمطبخ — هذه مهمة المشرف.

## 2. الوصول للوحة الإدارة

### مسارات الإدارة

| المسار | الوصف |
|--------|-------|
| `/admin/users` | إدارة المستخدمين |
| `/admin/requests` | طلبات الترقية |
| `/settings` | إعدادات الحساب الشخصي |
| `/analytics` | تحليلات شاملة لكل الفروع |
| `/reports` | تقارير عبر المنصة |

### أول دخول

1. استلام بيانات الدخول من فريق التقنية.
2. الدخول → فتح **«الإعدادات»** فورًا.
3. **تغيير كلمة المرور** الافتراضية.
4. تحديث **الاسم الكامل** والصورة الشخصية.

> هام: لا تشارك بيانات حساب المدير مع أي شخص آخر. أي إجراء من هذا الحساب يُسجَّل باسمك.

## 3. إدارة المنشآت والفروع

### بنية البيانات

```
المنشأة (Tenant)
└── الفروع (Branches)
    └── المستخدمون (Users)
        └── السجلات (Dish records, Alerts)
```

### إضافة فرع جديد

> حاليًا تُدار الفروع عبر بيانات المستخدم (`branch_id`, `branch_name`). للإضافة:

1. ادخل **«إدارة المستخدمين»** → **«إضافة مستخدم»**.
2. عند إنشاء أول مستخدم في الفرع الجديد، أدخل:
   - رقم الفرع (`branch_id`)
   - اسم الفرع (`branch_name`)
3. عند إنشاء مشرف للفرع، تأكّد من تطابق `branch_id`.

### عزل البيانات

- كل سجل (طبق، مخالفة، كاميرا) مرتبط بـ `tenant_id` و `branch_id`.
- المشرف لا يرى إلا بيانات فرعه.
- المدير يرى كل البيانات داخل المنشأة (Tenant).

## 4. إدارة المستخدمين

### الوصول

`/admin/users`

### قائمة المستخدمين

تظهر:
- الاسم الكامل
- البريد الإلكتروني
- اسم المستخدم (Username)
- الدور (admin / supervisor / staff)
- الفرع
- تاريخ الإنشاء
- آخر دخول

### إنشاء مستخدم جديد

1. اضغط **«إضافة مستخدم»**.
2. عبّئ:
   - الاسم الكامل
   - البريد الإلكتروني (يجب أن يكون فريدًا)
   - اسم المستخدم (يُولَّد تلقائيًا من البريد إن لم تُحدّده)
   - كلمة مرور مؤقتة (8 أحرف على الأقل)
   - **الدور**: staff / supervisor / admin
   - **الفرع** (`branch_id` + `branch_name`)
   - المشرف المسؤول (للموظفين)
3. اضغط **«حفظ»**.

### تعديل مستخدم

- يمكن تغيير: الاسم، الدور، الفرع، المشرف، البريد، كلمة المرور.
- لا يمكن حذف `id` أو `tenant_id` — هذه ثابتة.

### تعطيل / تفعيل

- التعطيل يمنع الدخول دون حذف البيانات.
- التفعيل يعيد الوصول.

### حذف مستخدم

- **الحذف لا يمسح سجلاته** (الأطباق والمخالفات تبقى محفوظة باسمه).
- استخدم الحذف فقط للحسابات المُختبرة أو المكرّرة.
- للموظف الذي ترك العمل: استخدم **التعطيل** بدلًا من الحذف.

### إعادة تعيين كلمة المرور

1. ادخل صفحة المستخدم.
2. اضغط **«إعادة تعيين كلمة المرور»**.
3. أدخل كلمة مرور مؤقتة قويّة.
4. أبلغ المستخدم بها — يجب تغييرها عند أول دخول.

## 5. طلبات ترقية الحسابات

### الوصول

`/admin/requests`

### كيف تعمل؟

- المستخدمون يستطيعون إرسال طلب ترقية الدور (مثلًا: من staff إلى supervisor).
- الطلب يصل لقائمة المدير العام.

### إجراءات المدير

| الإجراء | الوصف |
|---------|-------|
| **عرض** | قراءة سبب الطلب وبيانات المستخدم |
| **موافقة** | ترقية الدور تلقائيًا + إشعار |
| **رفض** | إغلاق الطلب مع سبب اختياري |

### نصائح

- تأكّد من هوية الموظف قبل الموافقة (تواصل مع مدير الفرع).
- لا تترك طلبات معلّقة طويلًا — راجع القائمة أسبوعيًا.

## 6. إعدادات النظام العامة

### الوصول

`/admin/settings` (إن كانت مفعّلة في النسخة الحالية).

### الإعدادات المتاحة

> تختلف الإعدادات المتاحة من إصدار لآخر. الحالية تشمل:

- **العلامة التجارية**: اسم المنصة المعروض.
- **توقيت العرض**: Asia/Riyadh (افتراضي — لا يُغيَّر).
- **سياسات التنبيهات**: مدة الحفظ، حدود الإشعارات.

### الإعدادات التقنية المتقدّمة

> هذه الإعدادات يديرها فريق التقنية عبر متغيّرات البيئة (راجع [`TECHNICAL_REQUIREMENTS_AR.md`](TECHNICAL_REQUIREMENTS_AR.md)):

- وضع الذكاء الاصطناعي (`PRODUCTION_AI_MODE`)
- مفاتيح Gemini / OpenAI
- إعدادات YOLO
- حدود رفع الملفات

## 7. إدارة الكاميرات على مستوى المنصة

### الوصول الإداري

- المدير يرى **جميع الكاميرات** في كل الفروع.
- المشرف يرى كاميرات فرعه فقط.

### الإحصاءات الإدارية

من لوحة التحليلات:
- **عدد الكاميرات النشطة** عبر المنصة.
- **معدّل المخالفات** لكل كاميرا.
- **أكثر الكاميرات تنبيهًا** (يدلّ على نقاط ضعف أو نشاط مرتفع).
- **الكاميرات غير المستخدمة** (للمراجعة).

### حذف كاميرات قديمة

> الحذف نهائي — تأكّد قبل التنفيذ.

1. ادخل صفحة الكاميرا.
2. اضغط **«حذف»**.
3. أكّد العملية.
4. الكاميرا تختفي من القوائم لكن **التنبيهات السابقة تبقى محفوظة** للأرشيف.

## 8. مراقبة أداء الذكاء الاصطناعي

### حالة AI الفورية

```
GET /api/v1/ai/status
```

تعرض:
- **حالة Gemini** للأطباق والمراقبة (متّصل / منقطع).
- **حالة YOLO** (محمَّل / غير محمَّل).
- **آخر استدعاء ناجح** (timestamp).
- **عدد الأخطاء الأخيرة**.

### مؤشّرات الأداء

| المؤشّر | المعنى | الإجراء عند المشكلة |
|---------|--------|---------------------|
| دقّة AI منخفضة (<70%) | اقتراحات الأطباق خاطئة بكثرة | راجع جودة الصور / دلائل الموظفين |
| YOLO يفشل تكرارًا | الأوزان غير محمّلة | تواصل مع التقنية لتحميل `hansung_ppe.pt` |
| تأخّر تحليل الإطار | الخادم بطيء أو الإطار كبير | اطلب من التقنية ضبط `YOLO_MAX_EDGE` |
| Gemini quota exceeded | تجاوز الحصة المجانية | اطلب ترقية الخطة أو إضافة مفتاح إضافي |

### تقارير دقّة شهرية

- يصدر فريق التقنية تقرير دقّة AI شهريًا (راجع `docs/PRODUCTION_ACCURACY_REPORT.md`).
- راجعه لاتخاذ قرارات تحسين النموذج.

## 9. التقارير الإدارية

### تقارير على مستوى المنشأة

المدير يستطيع بناء تقارير شاملة لكل الفروع:

- **مقارنة بين الفروع** — أداء كل فرع جنبًا إلى جنب.
- **اتجاهات زمنية** — تطوّر الأداء عبر الأشهر.
- **الموظفون الأكثر التزامًا** — أقل عدد مخالفات.
- **الفروع الأكثر مخالفات** — تستدعي تدخّلًا.

### التصدير

- جميع التقارير تدعم **تصدير Excel و PDF** (راجع [`CLIENT_GUIDE_AR.md`](CLIENT_GUIDE_AR.md) للتفاصيل).
- يمكن جدولة تقارير شهرية يدويًا (لا يوجد جدولة آلية حاليًا).

### مقاييس مقترحة للمتابعة

| المقياس | الهدف |
|---------|-------|
| نسبة الالتزام بالكمامة | ≥ 95% |
| نسبة الالتزام بالقفازات | ≥ 90% |
| متوسط دقّة AI للأطباق | ≥ 85% |
| تنبيهات معالَجة خلال 24 ساعة | ≥ 80% |
| تنبيهات أكثر من 7 أيام مفتوحة | 0 |

## 10. التدقيق وسجلات النشاط

### السجلات التلقائية

كل العمليات الحسّاسة تُسجَّل تلقائيًا:

- **تسجيل الدخول الناجح** — `user_id`, `role`, الوقت
- **تسجيل دخول فاشل** — الوقت فقط (بدون البريد لتجنّب enumeration)
- **مراجعة طبق** — `reviewer_id`, `reviewer_name`, `reviewed_at`
- **إغلاق مخالفة** — `resolved_by_id`, `resolved_by_name`, `resolved_at`
- **إنشاء/تعديل/حذف مستخدم** — في سجلات الخادم

### الوصول للسجلات

- السجلات الإدارية: قاعدة البيانات (PostgreSQL) — يصل إليها فريق التقنية.
- سجلات Render: لوحة Render Dashboard.

### الاحتفاظ بالسجلات

- **افتراضيًا**: لا يوجد حذف تلقائي.
- **يُوصى**: أرشفة السجلات الأقدم من سنة عبر `pg_dump`.

## 11. إدارة البيانات والصور

### حجم البيانات

| النوع | التقدير الشهري للمطعم متوسّط الحجم |
|-------|----------------------------------|
| سجلات الأطباق | 1,500 - 5,000 سجل |
| صور الأطباق | 50 - 200 ميجا بايت |
| تنبيهات المخالفات | 200 - 1,000 تنبيه |
| لقطات الإطارات | 100 - 500 ميجا بايت |

### مكان حفظ الصور

- **محليًا**: `backend/media/dishes/`
- **إنتاج Render**: `/var/data/ska/media/dishes/` (Persistent Disk)

### حذف صور قديمة (تنظيف)

> اطلب من فريق التقنية لا تنفّذ يدويًا.

سياسة موصى بها:
- صور أطباق أقدم من **سنتين** → أرشفة خارجية ثم حذف من القرص النشط.
- لقطات مخالفات تمّت معالجتها وأقدم من **سنة** → نفس السياسة.

## 12. إجراءات الطوارئ

### المنصة لا تستجيب

1. تحقّق من حالة Render: https://status.render.com
2. اختبر `https://taeen-quality-platform.onrender.com/health` (يجب يعود 200).
3. إذا كان الخادم نائمًا (Free Tier): الانتظار 60 ثانية كافٍ.
4. إن استمرّ التعطّل > 5 دقائق: تواصل مع التقنية فورًا.

### اشتباه باختراق

1. **غيّر `SECRET_KEY`** فورًا — يخرج كل المستخدمين تلقائيًا.
2. أعد تعيين كلمات مرور جميع المديرين والمشرفين.
3. راجع سجلات Render للنشاط المشبوه (محاولات دخول كثيرة، أوقات غير اعتيادية).
4. تواصل مع فريق الأمان (راجع [`SECURITY_GUIDE_AR.md`](SECURITY_GUIDE_AR.md)).

### فقدان بيانات

- **النسخ الاحتياطي اليومي** (PostgreSQL) يجب أن يكون مفعّلًا.
- استعادة من آخر نسخة: راجع [`DEPLOYMENT_GUIDE_AR.md`](DEPLOYMENT_GUIDE_AR.md).

### تسرّب بيانات اعتماد كاميرا

1. غيّر كلمة مرور الكاميرا فورًا من واجهتها (نظام الكاميرا).
2. حدّث الرابط في المنصة.
3. راجع من اطّلع على بيانات الاعتماد.

## 13. قائمة المهام الدورية

### يوميًا (5 دقائق)

- [ ] فحص قسم **«التنبيهات»** — لا توجد تنبيهات حرجة مفتوحة.
- [ ] التأكّد من عمل المنصة (دخول سريع).

### أسبوعيًا (15 دقيقة)

- [ ] مراجعة **طلبات الترقية** المعلّقة.
- [ ] فحص **التحليلات الأسبوعية**.
- [ ] مراجعة **التنبيهات غير المعالجة** أكثر من 3 أيام.
- [ ] مراجعة **حسابات المستخدمين الجديدة**.

### شهريًا (30 دقيقة)

- [ ] إصدار **تقرير شهري** للإدارة التنفيذية (Excel + PDF).
- [ ] مقارنة **أداء الفروع** والتعرّف على الأقل التزامًا.
- [ ] مراجعة **حسابات الموظفين الذين تركوا العمل** — تعطيلها.
- [ ] التواصل مع التقنية للتأكّد من **النسخ الاحتياطي** ودقّة AI.

### ربع سنوي (1 ساعة)

- [ ] **تدوير كلمة مرور المدير** الخاصة بك.
- [ ] **مراجعة شاملة** للمستخدمين والصلاحيات.
- [ ] **تقييم أداء AI** ومناقشة التحسينات مع التقنية.
- [ ] **حذف كاميرات قديمة** غير مستخدمة.

### سنويًا

- [ ] **مراجعة أمنية شاملة** (راجع [`SECURITY_GUIDE_AR.md`](SECURITY_GUIDE_AR.md)).
- [ ] **أرشفة بيانات قديمة** (سجلات أقدم من سنتين).
- [ ] **تجديد مفاتيح API** (Gemini, OpenAI إن كان مستخدمًا).
- [ ] **تقييم الترقية** للخطة المدفوعة على Render إن لزم.
