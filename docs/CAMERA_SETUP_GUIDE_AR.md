# دليل تكامل الكاميرات — منصة عين الجودة

> **CAMERA_SETUP_GUIDE_AR.md**
> آخر تحديث: مايو 2026
> الجمهور: العميل، مسؤول النظام، مشرف الموقع، فريق IT.
> الغرض: دليل احترافي لربط كاميرات المراقبة (CCTV) بمنصة **عين الجودة** وضمان جاهزية الذكاء الاصطناعي.

---

## 1. نظرة عامة

منصة **عين الجودة** تستقبل بثّ الفيديو من كاميرات المراقبة عبر بروتوكول **RTSP**، ثم تُحلّل الإطارات عبر محرك **YOLO** لاكتشاف المخالفات (معدات السلامة، النظافة، النفايات، وغيرها)، وتُعرض النتائج والتنبيهات في **لوحة المشرف**.

```
┌─────────────┐    RTSP     ┌─────────────┐    YOLO     ┌─────────────┐    API     ┌─────────────┐
│   الكاميرا   │ ──────────► │   Backend   │ ──────────► │   Alerts    │ ────────► │  Dashboard  │
│  (IP/ONVIF) │   H.264     │  (FastAPI)  │  Inference  │  (DB+Push)  │  Realtime │  (المشرف)   │
└─────────────┘             └─────────────┘             └─────────────┘           └─────────────┘
```

> **ملاحظة:** هذا الدليل يغطّي الإعداد من جهة العميل وIT. لا يتطلّب تعديلاً برمجياً من طرف المستخدم النهائي.

## 2. أنواع الكاميرات المدعومة

### 2.1 ملخص الدعم

| النوع / العلامة | الحالة | البروتوكول | ملاحظات |
|-----------------|--------|------------|---------|
| **IP Camera** (عام) | ✅ مدعوم | RTSP over TCP | أي كاميرا IP تُصدّر RTSP |
| **RTSP Camera** | ✅ مدعوم | RTSP | المعيار الأساسي للمنصة |
| **ONVIF** | ✅ مدعوم* | RTSP (عبر ONVIF Profile S) | *الاكتشاف التلقائي اختياري؛ الربط اليدوي عبر RTSP URL |
| **Hikvision** | ✅ مدعوم | RTSP | نماذج DS-2CD، iDS، AcuSense — الأكثر استخداماً في السوق السعودي |
| **Dahua** | ✅ مدعوم | RTSP | IPC-HFW، IPC-HDW — متوافقة |
| **Uniview** | ✅ مدعوم | RTSP | IPC2xx، IPC3xx |
| **Axis** | ✅ مدعوم | RTSP | M30، P32 — جودة ممتازة للمطابخ |

### 2.2 ما لا يُنصح به

| النوع | السبب |
|-------|--------|
| كاميرا USB / Webcam | للاختبار فقط — غير مناسبة للإنتاج |
| كاميرات Wi-Fi منخفضة الجودة | انقطاع متكرر، تأخير عالي |
| بث HTTP-MJPEG فقط | غير مدعوم كمسار إنتاجي؛ استخدم RTSP |
| كاميرات بدون RTSP | لا يمكن ربطها بالمنصة |

### 2.3 مواصفات الكاميرا الموصى بها (Hardware)

| البند | الحد الأدنى | المُوصى به |
|-------|-------------|------------|
| الدقة | 1080p (2 MP) | 4 MP (2560×1440) |
| الترميز | H.264 | H.264 Main Profile |
| H.265 | مدعوم* | *قد يتطلّب transcode على بعض الخوادم |
| IR / Night Vision | اختياري | تجنّب الاعتماد عليه نهاراً — النماذج RGB |
| PoE | — | موصى به لتغذية مستقرة |
| IP Rating | IP66 | IP67 للمطابخ الرطبة |

## 3. المتطلبات الأساسية

### 3.1 الشبكة

| المتطلب | التفاصيل |
|---------|----------|
| **نفس الشبكة المحلية (LAN)** | يجب أن يصل **خادم عين الجودة** (Backend) إلى الكاميرا عبر LAN أو VPN site-to-site |
| **عنوان IP ثابت** | Static IP أو DHCP Reservation لكل كاميرا (مثال: `192.168.1.101`) |
| **VLAN (اختياري)** | VLAN منفصل للكاميرات مع قواعد جدار ناري تسمح RTSP من الخادم فقط |
| **Bandwidth** | ~2–4 Mbps لكل كاميرا 1080p @ 15 FPS |
| **Latency** | < 100 ms داخل LAN |

### 3.2 إعدادات الكاميرا

| المتطلب | التفاصيل |
|---------|----------|
| **تفعيل RTSP** | من واجهة الكاميرا: Network → Advanced → RTSP → Enable |
| **منفذ RTSP** | الافتراضي **554** (قد يختلف: 8554، 10554) |
| **بيانات الدخول** | username + password (لا تترك admin/admin) |
| **Main Stream vs Sub Stream** | استخدم **Sub Stream** للتحليل (720p–1080p) لتقليل الحمل؛ Main للتسجيل المحلي إن لزم |

### 3.3 متطلبات الخادم (Backend)

| البند | القيمة |
|-------|--------|
| الوصول للكاميرا | Outbound TCP إلى `IP:554` (أو المنفذ المُعدّ) |
| FFmpeg / OpenCV | مُدمج في Backend لقراءة RTSP |
| جدار ناري | السماح من Backend → Cameras (ليس العكس للبث) |

### 3.4 قائمة تحقق قبل البدء

- [ ] عنوان IP ثابت لكل كاميرا
- [ ] RTSP مفعّل
- [ ] username/password آمن (8+ أحرف)
- [ ] اختبار ping من خادم Backend إلى IP الكاميرا
- [ ] اختبار RTSP عبر VLC (انظر القسم 4)
- [ ] إضاءة كافية في منطقة المراقبة (500+ lux)
- [ ] زاوية وارتفاع الكاميرا حسب القسم 6

## 4. استخراج رابط RTSP

### 4.1 البنية العامة

```
rtsp://[username]:[password]@[IP]:[PORT]/[path]
```

| الجزء | مثال | ملاحظة |
|-------|------|--------|
| username | admin | حساب الكاميرا |
| password | MyP@ss2026 | تجنّب `@` و `#` في كلمة المرور أو URL-encode |
| IP | 192.168.1.101 | Static IP |
| PORT | 554 | منفذ RTSP |
| path | /Streaming/Channels/102 | يختلف حسب الشركة |

### 4.2 Hikvision

**Main Stream (Channel 101):**
```
rtsp://admin:MyP@ss2026@192.168.1.101:554/Streaming/Channels/101
```

**Sub Stream (Channel 102) — مُوصى به للتحليل:**
```
rtsp://admin:MyP@ss2026@192.168.1.101:554/Streaming/Channels/102
```

**NVR (قناة 3، Sub Stream):**
```
rtsp://admin:MyP@ss2026@192.168.1.50:554/Streaming/Channels/302
```
*(302 = قناة 3، stream 02)*

**العثور على الرابط من الواجهة:**
1. Configuration → Network → Advanced Settings → Integration Protocol → Enable RTSP
2. أو: Configuration → Network → Platform Access → RTSP Port = 554

### 4.3 Dahua

**Main Stream:**
```
rtsp://admin:MyP@ss2026@192.168.1.102:554/cam/realmonitor?channel=1&subtype=0
```

**Sub Stream (subtype=1):**
```
rtsp://admin:MyP@ss2026@192.168.1.102:554/cam/realmonitor?channel=1&subtype=1
```

**NVR — قناة 2:**
```
rtsp://admin:MyP@ss2026@192.168.1.51:554/cam/realmonitor?channel=2&subtype=1
```

### 4.4 Uniview

```
rtsp://admin:MyP@ss2026@192.168.1.103:554/unicast/c1/s1/live
```
*(c1 = channel 1، s1 = sub stream؛ s0 = main)*

### 4.5 Axis

```
rtsp://root:MyP@ss2026@192.168.1.104:554/axis-media/media.amp?videocodec=h264&resolution=1280x720
```

### 4.6 Generic / ONVIF

```
rtsp://user:pass@192.168.1.105:554/stream1
rtsp://user:pass@192.168.1.105:8554/live
```

**اكتشاف ONVIF (أداة خارجية):**
- ONVIF Device Manager (Windows)
- أو `onvif-cli` — يعرض RTSP URL تلقائياً

### 4.7 اختبار الرابط قبل الإضافة للمنصة

**VLC Media Player:**
1. Media → Open Network Stream
2. الصق رابط RTSP
3. Play — يجب أن يظهر البث خلال 3–5 ثوان

**FFmpeg (سطر أوامر):**
```bash
ffprobe -rtsp_transport tcp "rtsp://admin:pass@192.168.1.101:554/Streaming/Channels/102"
```

## 5. إضافة الكاميرا داخل المنصة

### 5.1 الصلاحيات المطلوبة

| الدور | إضافة كاميرا | تعديل | حذف | اختبار اتصال |
|-------|--------------|-------|-----|--------------|
| Admin | ✅ | ✅ | ✅ | ✅ |
| Supervisor | ✅ (فرعه) | ✅ | — | ✅ |
| Staff | — | — | — | — |

### 5.2 خطوات الإضافة

1. **تسجيل الدخول** كـ Admin أو Supervisor.
2. الانتقال إلى **«الكاميرات»** أو **«إدارة الكاميرات»** من لوحة المشرف.
3. النقر على **«إضافة كاميرا»**.
4. تعبئة الحقول:

| الحقل | مثال | إلزامي |
|-------|------|--------|
| **اسم الكاميرا** | كاميرا التحضير — 1 | ✅ |
| **الموقع / المنطقة** | محطة التحضير الرئيسية | ✅ |
| **عنوان IP** | 192.168.1.101 | ✅ |
| **منفذ RTSP** | 554 | ✅ |
| **اسم المستخدم** | admin | ✅ |
| **كلمة المرور** | •••••••• | ✅ |
| **رابط RTSP** | rtsp://admin:...@192.168.1.101:554/... | ✅ |
| **الفرع** | فرع الرياض — 1 | ✅ (للمشرف: فرعه تلقائياً) |
| **ملاحظات** | Sub stream 102 | اختياري |

5. النقر على **«اختبار الاتصال»** (Test Connection).
6. عند النجاح: **«حفظ»** ثم **«تفعيل المراقبة»**.

### 5.3 نتائج اختبار الاتصال

| النتيجة | المعنى | الإجراء |
|---------|--------|---------|
| ✅ **متصل** | البث يعمل، إطار تجريبي مُستلم | احفظ وفعّل |
| ⚠️ **بطيء** | Latency > 3 ث | راجع الشبكة أو استخدم Sub Stream |
| ❌ **فشل المصادقة** | username/password خاطئ | راجع بيانات الدخول |
| ❌ **Timeout** | لا رد من الكاميرا | راجع IP، Firewall، RTSP مفعّل |
| ❌ **Black Screen** | اتصال بدون فيديو | راجع المسار (101 vs 102)، الترميز |

## 6. أفضل إعدادات الكاميرات للذكاء الاصطناعي

### 6.1 الدقة (Resolution)

| الاستخدام | الدقة | Stream |
|-----------|-------|--------|
| **تحليل AI (YOLO)** | 1280×720 – 1920×1080 | Sub Stream |
| **تسجيل أدلة عالية الدقة** | 2560×1440 | Main Stream (اختياري) |
| **تجنّب** | 4K للتحليل المباشر | حمل CPU/GPU مرتفع |

### 6.2 معدل الإطارات (FPS)

| الإعداد | القيمة | السبب |
|---------|--------|-------|
| **Capture FPS** | 10–15 FPS | كافٍ للمطبخ؛ YOLO يحلّل كل 3–5 ث |
| **Analysis interval** | 1 إطار / 3–5 ث | مُضبوط في Backend |
| **تجنّب** | 30 FPS للتحليل | استهلاك غير ضروري |

### 6.3 الإضاءة (Lighting)

| البند | التوصية |
|-------|---------|
| **الشدة** | 500–750 lux في محطات التحضير |
| **نوع الإضاءة** | LED 4000K–5000K (أبيض محايد) |
| **تجنّب** | إضاءة صفراء (< 3000K)، IR نهاراً |
| **النوافذ** | لا تضع الكاميرات مقابل نافذة مباشرة (Backlight) |

### 6.4 الزاوية (Angle)

| المنطقة | الميل (Tilt) | مجال الرؤية |
|---------|--------------|-------------|
| محطة التحضير | 25°–35° | 90°–110° |
| الغسيل | 30°–40° | 90° |
| الممرات | 15°–25° | 110° |
| **تجنّب** | 90° (من الأعلى فقط) | يُخفي الوجه واليدين |
| **تجنّب** | 0° (أفقي) | لا ترى الأرضية |

### 6.5 الارتفاع (Height)

| البند | القيمة |
|-------|--------|
| **الارتفاع عن الأرض** | 2.4 – 3.0 م |
| **مسافة العامل** | 2 – 6 م |
| **حجم العامل في الإطار** | 20% – 60% من ارتفاع الصورة |
| **اليدين (قفازات)** | ≥ 50 بكسل ارتفاعاً في 1080p |

## 7. المشاكل الشائعة وحلولها

### 7.1 شاشة سوداء (Black Screen)

| السبب المحتمل | الحل |
|---------------|------|
| مسار RTSP خاطئ (101 vs 102) | جرّب Channel 102 (Sub) أو subtype=1 |
| الترميز H.265 غير مدعوم | غيّر إلى H.264 في إعدادات الكاميرات |
| الكاميرات في وضع Sleep | عطّل Power Saving في Network |
| VLAN / Firewall | تأكد من السماح TCP 554 من Backend |

### 7.2 Timeout (انتهاء المهلة)

| السبب | الحل |
|-------|------|
| IP خاطئ أو الكاميرات offline | `ping 192.168.1.101` |
| RTSP معطّل | فعّل RTSP من واجهة الكاميرات |
| منفذ مغلق | افتح 554 (أو المنفذ المُعدّ) |
| Backend خارج LAN | استخدم VPN site-to-site |

### 7.3 Authentication Failed (فشل المصادقة)

| السبب | الحل |
|-------|------|
| username/password خاطئ | راجع من واجهة الكاميرات؛ أعد تعيين كلمة المرور |
| Lockout بعد محاولات فاشلة | انتظر 30 دقيقة أو أعد تشغيل الكاميرات |
| أحرف خاصة في كلمة المرور | URL-encode: `@` → `%40`، `#` → `%23` |

### 7.4 بث غير مستقر (Unstable Stream)

| السبب | الحل |
|-------|------|
| Wi-Fi ضعيف | استخدم Ethernet (PoE) |
| Bandwidth مشترك | VLAN أو QoS للكاميرات |
| Sub stream بدل Main | قلّل الدقة إلى 720p |
| RTSP over UDP | استخدم **RTSP over TCP** في Backend |

### 7.5 إطارات مفقودة (Dropped Frames)

| السبب | الحل |
|-------|------|
| Backend مشغول (YOLO) | طبيعي في Live mode — إطار واحد في كل مرة |
| FPS الكاميرات عالي جداً | خفّض إلى 15 FPS |
| Latency شبكة | راجع `GET /api/v1/ai/health` — drop_ratio |
| CPU مُحمّل | ترقية الخادم أو GPU (انظر COST_BREAKDOWN_AR.md) |

### 7.6 جدول استكشاف الأخطاء السريع

| العرض | الخطوة 1 | الخطوة 2 | الخطوة 3 |
|-------|----------|----------|----------|
| لا اتصال | ping IP | VLC + RTSP URL | Firewall 554 |
| فيديو بدون صوت | — | — | الصوت غير مطلوب للAI |
| تحليل بطيء | Sub stream | `/ai/health` latency | ترقية CPU |
| تنبيهات كثيرة خاطئة | إضاءة + زاوية | ACCURACY_REPORT_AR.md | إعادة تدريب |

## 8. نصائح تحسين دقة الذكاء الاصطناعي

### 8.1 تجنّب الإضاءة الخلفية (Backlight)

```
❌ خطأ                          ✅ صحيح
┌──────────────────┐            ┌──────────────────┐
│  نافذة ☀️        │            │  جدار / إضاءة    │
│       📷         │            │       📷         │
│    👤 (ظل)       │            │    👤 (واضح)     │
└──────────────────┘            └──────────────────┘
```

### 8.2 إضاءة مستقرة

- تجنّب وميض (Flicker) — استخدم LED quality.
- تجنّب ظلال قوية على الوجه (كمامة vs ظل).
- راجع `AI_DATASET_GUIDE_AR.md` — القسم 4 (الإضاءة).

### 8.3 زاوية المطبخ الصحيحة

- **لا** كاميرات سقفية 90° فقط — لا ترى الوجه ولا اليدين.
- **نعم** 25°–35° من ارتفاع 2.6 م — ترى الرأس، الجذع، اليدين، جزء من الأرضية.

### 8.4 تجنّب كاميرات السقف فقط (Ceiling-Only)

| المشكلة | الأثر على AI |
|---------|--------------|
| رؤية من الأعلى | لا كمامة، لا قفازات، لا زي |
| رأس صغير | no_headcover ضعيف |
| يدان غير مرئيتين | no_gloves = 0% |

### 8.5 قائمة تحقق الدقة

- [ ] إضاءة ≥ 500 lux
- [ ] لا Backlight
- [ ] زاوية 25°–35° (ليس 90°)
- [ ] ارتفاع 2.4–3.0 م
- [ ] Sub stream 720p–1080p
- [ ] 10–15 FPS
- [ ] H.264

### 9.1 مخطط تدفق البيانات

```
┌─────────────────────────────────────────────────────────────────────────────┐
```

## 11. ملخص سريع للعميل

1. **الكاميرات:** IP/RTSP — Hikvision، Dahua، Uniview، Axis مدعومة.
2. **الشبكة:** نفس LAN، IP ثابت، RTSP مفعّل، بيانات دخول آمنة.
3. **الرابط:** `rtsp://user:pass@IP:554/path` — اختبر بـ VLC أولاً.
4. **المنصة:** أضف IP، username، password، RTSP URL → **اختبار اتصال** → حفظ.
5. **AI:** 720p–1080p، 10–15 FPS، إضاءة 500+ lux، زاوية 25°–35°، ارتفاع 2.6 م.
6. **المشاكل:** Black screen → مسار/ترميز؛ Timeout → IP/Firewall؛ Auth → كلمة المرور.
