## 1. نظرة عامة على المنصة

### الوصف

**عين الجودة** منصة سحابية/هجينة لمراقبة جودة وسلامة المطابخ في قطاع الضيافة والمطاعم. تجمع بين:

| القدرة | التقنية |
|--------|---------|
| توثيق الأطباق بالذكاء الاصطناعي | Google Gemini Vision |
| كشف مخالفات السلامة (PPE) | YOLOv8 (Ultralytics) |
| إدارة الكاميرات والتنبيهات | FastAPI + React |
| التقارير والتحليلات | Recharts + Excel/PDF Export |
| العزل متعدد الفروع | Multi-tenant PostgreSQL |

### المكوّنات الرئيسية

```
┌─────────────────────────────────────────────────────────────┐
│  Frontend (React SPA)          ← المتصفّح / الجوال           │
├─────────────────────────────────────────────────────────────┤
│  Backend API (FastAPI)         ← منطق الأعمال + المصادقة    │
├─────────────────────────────────────────────────────────────┤
│  AI Inference Engine           ← YOLO + Gemini Vision       │
├─────────────────────────────────────────────────────────────┤
│  Database (PostgreSQL)         ← البيانات والسجلات           │
├─────────────────────────────────────────────────────────────┤
│  Media Storage (SSD/NAS)       ← صور الأطباق + لقطات المخالفات│
└─────────────────────────────────────────────────────────────┘
         ▲ RTSP
         │
  ┌──────┴──────┐
  │ IP Cameras  │
  └─────────────┘
```

## 4. متطلبات الكاميرات

### 4.1 النوع المطلوب

| النوع | الحالة |
|-------|--------|
| **كاميرات IP (Network Cameras)** | ✅ **مطلوبة** — النوع الوحيد المدعوم |
| كاميرات USB / Webcam | ⚠️ للاختبار اليدوي فقط (تحليل لقطة) |
| كاميرات Analog (CVBS) | ❌ غير مدعومة مباشرة (تحتاج NVR يحوّل لـ RTSP) |
| كاميرات Wi-Fi بدون RTSP | ❌ غير مدعومة |

### 4.2 بروتوكول RTSP (إلزامي)

يجب أن تدعم الكاميرا بروتوكول **RTSP** (Real Time Streaming Protocol) لربطها بالمنصة.

#### صيغة RTSP المدعومة

```
rtsp://[username]:[password]@[IP_ADDRESS]:[PORT]/[stream_path]
```

#### أمثلة واقعية

```
# Hikvision
rtsp://admin:CameraPass123@192.168.1.101:554/Streaming/Channels/101

# Dahua
rtsp://admin:CameraPass123@192.168.1.102:554/cam/realmonitor?channel=1&subtype=0

# Axis
rtsp://root:CameraPass123@192.168.1.103:554/axis-media/media.amp

# Uniview
rtsp://admin:CameraPass123@192.168.1.104:554/unicast/c1/s0/live

# عام (Generic ONVIF)
rtsp://admin:CameraPass123@192.168.1.105:554/stream1
```

> **تحذير أمني:** بيانات الاعتماد تُخزَّن مشفّرة في قاعدة البيانات وتُعرض مموَّهة في الواجهة (`rtsp://***:***@host`).

### 4.3 الدقة الموصى بها

| الاستخدام | الدقة | الملاحظة |
|-----------|-------|----------|
| **كشف PPE (كمامة/قفازات)** | 1080p (1920×1080) | ✅ **الموصى به** |
| كشف PPE (حد أدنى) | 720p (1280×720) | ⚠️ مقبول مع إضاءة جيدة |
| توثيق الأطباق (جوال) | 1080p+ | يكفي 720p للأطباق البسيطة |
| كشف النفايات/الأرضية | 1080p | يحتاج رؤية واسعة للمنطقة |
| **غير موصى به** | أقل من 480p | دقة غير كافية لـ AI |

### 4.4 معدّل الإطارات (FPS)

| السيناريو | FPS مطلوب | ملاحظة |
|-----------|-----------|--------|
| تحليل PPE مستمر | 1-2 fps للتحليل | الكاميرا تبث 25/30 fps، AI يحلّل 1-2 إطار/ثانية |
| تحليل يدوي (لقطة) | إطار واحد عند الطلب | لا حاجة لبث مستمر |
| تسجيل الأدلة | 15-25 fps | للفيديو المخزَّن |
| **الحد الأدنى للكاميرا** | 15 fps بث | أقل من ذلك يؤثر على جودة اللقطات |

> المنصة تحلّل **إطارًا واحدًا كل 1-3 ثوانٍ** في الوضع المستمر — لا حاجة لكاميرات 60 fps.

### 4.5 متطلبات الشبكة للكاميرات

| المتطلب | المواصفة |
|---------|----------|
| **نوع الشبكة** | Ethernet (كابل) موصى به — Wi-Fi مقبول للاختبار |
| **VLAN** | يُوصى بفصل كاميرات المطبخ في VLAN مستقل |
| **PoE** | موصى به (كاميرات PoE تقلّل الفوضى) |
| **عرض النطاق لكل كاميرا 1080p** | 4-8 Mbps |
| **عرض النطاق لكل كاميرا 720p** | 2-4 Mbps |
| **المنفذ** | TCP 554 (RTSP) — يجب أن يكون مفتوحًا داخليًا |
| **ONVIF** | مدعوم اختياريًا (للاكتشاف التلقائي) |

#### جدول عرض النطاق حسب عدد الكاميرات

| عدد الكاميرات | 1080p (Mbps) | 720p (Mbps) | التوصية |
|---------------|-------------|-------------|---------|
| 1-2 | 8-16 | 4-8 | 100 Mbps switch |
| 3-6 | 24-48 | 12-24 | 1 Gbps switch |
| 7-12 | 56-96 | 28-48 | 1 Gbps + VLAN |
| 13-24 | 104-192 | 52-96 | 1 Gbps dedicated + QoS |

## 5. متطلبات الإنترنت والشبكة

### 5.1 سرعة الإنترنت

| الاستخدام | الحد الأدنى | الموصى به |
|-----------|-------------|-----------|
| **المنصة السحابية (Render)** | 10 Mbps تحميل / 5 Mbps رفع | 50/20 Mbps |
| **خادم ذاتي (Self-hosted)** | 20 Mbps تحميل / 10 Mbps رفع | 100/50 Mbps |
| **تحليل AI (Gemini API)** | 5 Mbps مستقر | 20 Mbps |
| **رفع صور الأطباق (جوال)** | 2 Mbps رفع | 10 Mbps |
| **تصدير تقارير** | 5 Mbps تحميل | 20 Mbps |

> **ملاحظة:** الكاميرات RTSP تعمل على **الشبكة المحلية** ولا تحتاج إنترنت — الإنترنت مطلوب للوصول للمنصة السحابية وGemini API فقط.

### 5.2 الشبكة المحلية المستقرة

| المتطلب | المواصفة |
|---------|----------|
| **نوع الشبكة** | Ethernet موصى به للكاميرات والخادم |
| **Switch** | Managed switch مع VLAN (للمطاعم المتوسطة+) |
| **Router/Firewall** | يدعم Port Forwarding إن لزم |
| **Latency داخلي** | < 5 ms بين الكاميرا والخادم |
| **Packet Loss** | < 0.1% |
| **Uptime الشبكة** | 99.9% (للمراقبة المستمرة) |

### 5.3 عرض النطاق الموصى به (مطعم متوسط — 6 كاميرات)

```
┌────────────────────────────────────────────────────────┐
│  عرض النطاق المطلوب — مطعم متوسط (6 كاميرات)          │
├────────────────────────────────────────────────────────┤
│  كاميرات RTSP (6 × 1080p)    : 48 Mbps (محلي)         │
│  وصول الموظفين للمنصة        : 10 Mbps (إنترنت)        │
│  Gemini API (تحليل أطباق)    :  2 Mbps (إنترنت)        │
│  رفع لقطات يدوية             :  5 Mbps (إنترنت)        │
├────────────────────────────────────────────────────────┤
│  إجمالي الشبكة المحلية       : 1 Gbps switch           │
│  إجمالي الإنترنت الموصى به   : 50/20 Mbps              │
└────────────────────────────────────────────────────────┘
```

### 5.4 المنافذ المطلوبة (Firewall)

| المنفذ | البروتوكول | الاتجاه | الغرض |
|--------|-----------|---------|-------|
| `443` | HTTPS | Inbound | الوصول للمنصة |
| `80` | HTTP | Inbound | إعادة توجيه لـ HTTPS |
| `554` | RTSP | Internal | بث الكاميرات (داخلي فقط) |
| `5432` | PostgreSQL | Internal | قاعدة البيانات (داخلي فقط) |
| `8000` | HTTP | Internal | Backend API (داخلي) |

> **لا تفتح منفذ 554 للإنترنت العام** — الكاميرات يجب أن تكون على شبكة داخلية فقط.

### 6.4 وضع CPU الاحتياطي (Fallback)

عند عدم توفر GPU، يعمل YOLO على CPU تلقائيًا:

| الإعداد | القيمة | التأثير |
|---------|--------|---------|
| `YOLO_ENABLED=true` | مفعّل | YOLO يعمل |
| `YOLO_USE_PERSON_DETECTOR=false` | معطّل | يوفر ~50% RAM |
| `YOLO_MAX_EDGE=480` | صورة أصغر | أسرع لكن أقل دقة |
| `OMP_NUM_THREADS=4` | 4 خيوط | توازن سرعة/استهلاك |

> **تحذير:** على CPU، تحليل 6 كاميرات متزامنة قد يستغرق 12-24 ثانية/دورة — غير مناسب للمراقبة الفورية.

### 8.2 جدار الحماية (Firewall)

```
القواعد الأساسية:
✅ السماح: 443 (HTTPS) من الإنترنت
✅ السماح: 554 (RTSP) داخلي فقط (شبكة الكاميرات)
✅ السماح: 22 (SSH) من IPs إدارية محددة فقط
❌ حظر: 5432 (PostgreSQL) من الإنترنت
❌ حظر: 8000 (Backend) من الإنترنت مباشرة
❌ حظر: جميع المنافذ غير المستخدمة
```

### 8.3 VPN (موصى به)

| السيناريو | التوصية |
|-----------|---------|
| وصول المشرفين عن بُعد | VPN (WireGuard / OpenVPN) |
| ربط فروع متعددة | Site-to-Site VPN |
| إدارة الخوادم | VPN + SSH Key فقط (لا SSH بكلمة مرور) |
| الوصول للكاميرات عن بُعد | VPN — **لا** تفتح RTSP للإنترنت |

### 8.4 كلمات المرور الآمنة

| المعيار | المواصفة |
|---------|----------|
| **الحد الأدنى** | 8 أحرف |
| **الموصى به** | 16+ حرف (أحرف كبيرة/صغيرة + أرقام + رموز) |
| **JWT Secret** | ≥ 32 حرف عشوائي (`openssl rand -hex 32`) |
| **كاميرات RTSP** | كلمة مرور فريدة لكل كاميرا |
| **قاعدة البيانات** | كلمة مرور ≥ 20 حرف |
| **التدوير** | كل 90 يومًا للمشرفين، كل 6 أشهر لـ SECRET_KEY |

### 8.5 استراتيجية النسخ الاحتياطي

| العنصر | التكرار | الاحتفاظ | الأداة |
|--------|---------|----------|--------|
| **PostgreSQL** | يومي (3:00 AM) | 30 يومًا | `pg_dump` / Render Auto-backup |
| **صور الأطباق** | يومي | 90 يومًا | `rsync` / NAS sync |
| **لقطات المخالفات** | يومي | 365 يومًا | NAS |

### 13.1 دقة AI تعتمد على زوايا الكاميرا

| العامل | التأثير على الدقة |
|--------|-------------------|
| **زاوية الكاميرا** | الكاميرا يجب أن ترى **وجه ويدي** الموظف بوضوح — الكاميرا من الأعلى فقط تُفوّت الكمامة |

| **الزاوية المثالية** | 30-45° من الأفقي (ليس عمودي 90°) |
| **تغطية المنطقة** | كاميرا واحدة تغطي 20-40 م² بكفاءة |
| **الأعمدة والعوائق** | تُعيق الرؤية — خطّط المواقع مسبقًا |

```
✅ زاوية جيدة:              ❌ زاوية سيئة:
   كاميرا ╲                    كاميرا │
          ╲ 30°                        │ 90°
    👤 وجه واضح                  👤 رأس فقط
    🧤 يدين واضحة               🧤 يدين مخفية
```

### 13.2 الإضاءة المناسبة مطلوبة

| العامل | التأثير |
|--------|---------|
| **إضاءة كافية** (> 300 lux في منطقة العمل) | دقة أعلى 15-25% |
| **إضاءة خافتة / ظلال قوية** | انخفاض دقة · تنبيهات إيجابية كاذبة |
| **إضاءة خلفية (نافذة خلف الموظف)** | Silhouette — يصعب رؤية الوجه |
| **وميض / إضاءة نيون** | يؤثر على استقرار الكشف |

**توصيات الإضاءة:**
- LED panel 4000K-5000K فوق مناطق التحضير
- تجنّب الإضاءة الخلفية المباشرة
- توحيد الإضاءة عبر المطبخ

### 13.3 إعادة التدريب المستمر تُحسّن الدقة

| المرحلة | الدقة المتوقعة | الإجراء |
|---------|----------------|---------|
| **نشر أولي (نموذج عام)** | 70-80% | استخدام `hansung_ppe.pt` الافتراضي |
| **بعد شهر جمع بيانات** | 80-88% | جمع 500+ صورة من مطبخ العميل |
| **بعد إعادة تدريب مخصّص** | 88-93% | `ppe_train_all.py` على بيانات العميل |
| **بعد 3 أشهر تحسين مستمر** | 90-95% | تدريب دوري + مراجعة التنبيهات |

**عملية التحسين:**

```
1. تشغيل المنصة لمدة 2-4 أسابيع (جمع بيانات حقيقية)
         │
2. تصنيف 500-1000 صورة من مطبخ العميل
   (صحيح / مخالفة / يحتاج مراجعة)
         │
3. إعادة تدريب YOLO على البيانات المخصّصة
   (scripts/ppe_train_all.py)
         │
4. اختبار الدقة: scripts/ppe_accuracy_test.py
         │
5. نشر النموذج الجديد → رفع الدقة 10-15%
         │
6. تكرار كل 3-6 أشهر
```

### 13.4 عوامل أخرى تؤثر على الأداء

| العامل | التأثير | التوصية |
|--------|---------|---------|
| **عدد الأشخاص في الإطار** | > 5 أشخاص = أبطأ وأقل دقة | كاميرا لكل 20-30 م² |
| **الزي الموحّد** | ألوان غير مدربة = false positives | تدريب مخصّص على أزياء العميل |
| **نوع القفازات** | قفازات ملونة قد لا تُكتشف | تدريب على أنواع القفازات المستخدمة |
| **نوع غطاء الرأس** | شماغ/كوفية/بونيه — دقة مختلفة | تدريب على الأنواع المحلية |
| **حركة سريعة** | Motion blur يُخفّض الدقة | كاميرا ≥ 25 fps + إضاءة جيدة |
| **انعكاسات (زجاج/ستانلس)** | False positives | تجنّب التوجيه المباشر |

### 13.5 ضمانات واقعية

| ما تضمنه المنصة | ما لا تضمنه |
|-----------------|-------------|
| ✅ تشغيل مستقر 99% uptime (خطة مدفوعة) | ❌ دقة 100% في كل الظروف |
| ✅ كشف المخالفات الواضحة (> 85% ثقة) | ❌ العمل بدون كاميرات مناسبة |
| ✅ حفظ دائم للسجلات والصور | ❌ دقة عالية في إضاءة رديئة |
| ✅ تقارير وتصدير فوري | ❌ كشف بدون إنترنت (Gemini API) |
| ✅ عزل بيانات بين الفروع | ❌ دقة فورية من اليوم الأول بدون تدريب |
| ✅ تحديثات أمنية دورية | ❌ استبدال المشرف البشري |
