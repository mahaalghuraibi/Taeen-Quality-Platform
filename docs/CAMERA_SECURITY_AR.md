## 1. الهدف والمبدأ الأساسي

**لا تُعرَّض كاميرات المطعم على الإنترنت العام.**

- لا روابط RTSP عامة.
- لا Port Forwarding لمنفذ **554** (RTSP) أو منافذ بث الكاميرا.
- البث الخام (Raw RTSP) يعمل **داخل شبكة المطعم المحلية (LAN/VLAN)** فقط.
- المنصة السحابية تستقبل **نتائج التحليل فقط**: تنبيهات، طوابع زمنية، لقطات أدلة (Snapshots)، وليس بثاً مباشراً مستمراً للعميل النهائي عبر الإنترنت إلا عبر قنوات مشفّرة (HTTPS) وصلاحيات JWT.

## 2. المعمارية الآمنة الموصى بها

| الطبقة | الوصف |
|--------|--------|
| **كاميرات IP** | داخل شبكة المطعم — عناوين `192.168.x.x` أو `10.x.x.x` |
| **VLAN للكاميرات** | شبكة منفصلة عن شبكة الموظفين والضيوف (إن أمكن) |
| **خادم / وكيل AI محلي** | جهاز داخل نفس LAN يقرأ RTSP محلياً |
| **YOLO / التحليل** | يعمل على الخادم المحلي أو على السحابة من **إطارات** وليس بث RTSP عام |
| **المنصة السحابية** | HTTPS فقط — JWT — RBAC — PostgreSQL |
| **ما يُرسل للسحابة** | نتائج المخالفات، التنبيهات، metadata، صور أدلة مضغوطة |

### تدفق البيانات (مختصر)

```
[كاميرات CCTV] --RTSP داخل LAN--> [وكيل AI / خادم محلي]
                                        |
                                        | HTTPS (نتائج فقط)
                                        v
                              [Backend عين الجودة — Render]
                                        |
                                        | HTTPS
                                        v
                              [لوحة المشرف — متصفح]
```

## 3. معمارية ممنوعة (خطر)

| الممارسة | لماذا خطرة |
|----------|------------|
| فتح RTSP على IP عام | أي شخص قد يرى المطبخ ويستغل الثغرة |
| Port Forward 554 → كاميرا | هجوم Brute-force على كلمة مرور الكاميرا |
| DDNS عام بدون VPN | نفس مخاطر التعريض العام |
| بث خام عبر HTTP عام | اعتراض غير مشفّر |
| إدخال RTSP كامل في الواجهة الأمامية للعميل | تسريب credentials في المتصفح / السجلات |

**المنصة تحذّر تلقائياً** عند اكتشاف IP عام أو كلمة مرور افتراضية وتعرض حالة **«خطر»**.

## 4. مخطط الشبكة

```
                    الإنترنت (محظور لـ RTSP)
                           |
                    [جدار ناري / Router]
                     يحظر 554 من WAN
                           |
        +------------------+------------------+
        |                  |                  |
   [VLAN موظفين]    [VLAN كاميرات]     [خادم AI محلي]
   Wi-Fi ضيوف       192.168.50.0/24    يقرأ RTSP فقط
                           |                  |
                    [Cam1][Cam2][Cam3] ------> YOLO
                                              |
                                         HTTPS فقط
                                              |
                                    [عين الجودة — Cloud API]
```

## 5. قواعد أمان الشبكة

| # | القاعدة |
|---|---------|
| 1 | كاميرات على **LAN/VLAN** داخلية فقط |
| 2 | **VLAN منفصل** للكاميرات عند الإمكان |
| 3 | كلمات مرور قوية — تعطيل الحسابات الافتراضية `admin` / `123456` |
| 4 | تعطيل الخدمات غير المستخدمة على الكاميرا (Telnet, FTP, UPnP) |
| 5 | السماح لـ RTSP **فقط** من IP خادم التحليل المحلي |
| 6 | **حظر** الوصول الخارجي لمنفذ 554 |
| 7 | **VPN** (WireGuard / IPSec) للوصول عن بُعد للفروع |
| 8 | المنصة عبر **HTTPS** فقط |
| 9 | لا تسجيل (Logging) لكلمات مرور الكاميرا في الخادم |

## 6. حماية بيانات اعتماد الكاميرا

| الإجراء | التطبيق في المنصة |
|---------|-------------------|
| تخزين مشفّر | رابط RTSP يُخزَّن مشفّراً (Fernet + `SECRET_KEY`) في PostgreSQL |
| عدم إرجاع credentials | API يُرجع `rtsp://***:***@host:port/path` فقط |
| إخفاء في الواجهة | حقول كلمة المرور من نوع `password` — عرض IP مموّه |
| عدم التسجيل | لا تُسجَّل كلمات المرور في logs التطبيق |
| التقييم الأمني | `POST /api/v1/supervisor/cameras/security-assess` قبل الحفظ |

## 7. ما يطبّقه النظام تلقائياً

### Backend (`app/security/`)

- `camera_security.py` — تقييم: IP عام، كلمة مرور ضعيفة، DDNS، HTTP غير آمن.
- `stream_url_crypto.py` — تشفير عند التخزين ببادئة `enc:v1:`.
- `stream_url.py` — تحقق من صحة الرابط + إخفاء credentials في JSON.

### Frontend

- `utils/cameraSecurity.js` — تحذيرات فورية عند إدخال رابط RTSP.
- بطاقة الكاميرا تعرض: **آمن** | **يحتاج مراجعة** | **خطر**.

---

## 8. حالات الأمان في الواجهة

| الحالة | المعنى | لون الواجهة |
|--------|--------|-------------|
| **آمن** | IP خاص (RFC1918) + كلمة مرور قوية + RTSP داخل LAN | أخضر |
| **يحتاج مراجعة** | رابط ناقص، localhost، أو hostname غير محلي | كهرماني |
| **خطر** | IP عام، كلمة مرور افتراضية، HTTP عام، DDNS معرّض | أحمر |

## 9. قائمة فحص إعداد الكاميرا

- [ ] الكاميرا على شبكة محلية `192.168.x.x` / `10.x.x.x`
- [ ] لا يوجد Port Forwarding لمنفذ 554 من الراوتر
- [ ] تم تغيير كلمة مرور الكاميرا الافتراضية
- [ ] تم تعطيل حساب admin الافتراضي أو تقوية كلمة مروره
- [ ] RTSP مسموح فقط من IP خادم التحليل
- [ ] تم اختبار الاتصال من داخل المطعم فقط
- [ ] المنصة تعرض حالة **آمن** أو تم معالجة التحذيرات
- [ ] HTTPS مفعّل للوصول للوحة التحكم
- [ ] صلاحيات المستخدمين (Admin / Supervisor / Staff) مضبوطة

## 10. قواعد الجدار الناري

### على Router / Gateway (WAN → LAN)

| الاتجاه | المنفذ | الإجراء |
|---------|--------|---------|
| WAN → LAN | 554/tcp | **DENY** (RTSP) |
| WAN → LAN | 80, 443 للكاميرا | **DENY** (واجهة ويب الكاميرا) |
| LAN → WAN | عام | حسب سياسة العميل |

### على VLAN الكاميرات

| المصدر | الوجهة | المنفذ | الإجراء |
|--------|--------|--------|---------|
| خادم AI | كاميرات | 554 | **ALLOW** |
| شبكة الموظفين | كاميرات | 554 | **DENY** (موصى به) |
| الإنترنت | كاميرات | أي | **DENY** |

## 11. VPN للوصول عن بُعد

للمشرفين الذين يحتاجون مراقبة فرع عن بُعد:

1. استخدم **VPN** إلى شبكة المطعم (لا تعرّض RTSP مباشرة).
2. بعد الاتصال بـ VPN، افتح المنصة عبر HTTPS.
3. لا تشارك روابط RTSP عبر واتساب أو بريد.

## 12. مسؤوليات فريق IT لدى العميل

| المسؤولية | التفاصيل |
|-----------|----------|
| **الشبكة** | VLAN، Firewall، منع Port Forward للكاميرات |
| **الكاميرات** | كلمات مرور قوية، تحديث firmware |
| **الخادم المحلي** | تشغيل وكيل القراءة من RTSP (إن وُجد) |
| **النسخ الاحتياطي** | NVR محلي + سياسة احتفاظ |
| **الوصول** | VPN للفروع — MFA للحسابات الحساسة |
| **الامتثال** | عدم مشاركة بث المطبخ خارج المنشأة |
