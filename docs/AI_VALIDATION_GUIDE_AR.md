## 1. لماذا لا يوجد دقة 100%؟

أنظمة الرؤية الحاسوبية **لا تصل أبداً إلى دقة 100%** في الواقع، وأي جهة تدّعي ذلك تكون غير صادقة. الأسباب:

| السبب | الأثر |
|-------|-------|
| **الإضاءة المتغيرة** | الظلال والإضاءة الخلفية تربك النموذج |
| **زاوية الكاميرا** | الأجسام من زوايا غير مألوفة تُكتشف بصعوبة |
| **حركة الأشخاص** | ضبابية الحركة (motion blur) تخفي التفاصيل |
| **التداخل (occlusion)** | شخص يحجب آخر، أو يد تحجب قفازاً |
| **تنوّع الواقع** | أشكال كمامات/قفازات/أزياء لا حصر لها |
| **جودة الكاميرا** | دقة منخفضة أو ضغط عالٍ يفقد التفاصيل |

**الهدف الواقعي:** دقة عالية وقابلة للقياس لكل فئة (مثلاً 80–95%)، مع تقرير شفاف بالأخطاء (إنذارات كاذبة + مخالفات فائتة)، وليس رقماً مثالياً.

## 2. كيف تجمع صور اختبار حقيقية من كاميرات المطعم

1. **استخدم الكاميرات الفعلية** المثبتة في المطعم (نفس الزاوية ونفس الدقة المستخدمة في الإنتاج).
2. التقط لقطات في أوقات مختلفة من اليوم (صباح/ظهر/مساء) لتغطية الإضاءة.
3. صوّر حالات **مخالفة** وحالات **سليمة** لكل فئة.
4. احفظ الصور في المجلد المطابق تحت `datasets/validation/`.
5. لا تُعِد استخدام صور التدريب نفسها — صور التحقق يجب أن تكون **جديدة** لم يرها النموذج.

> **خصوصية:** صور التحقق قد تحتوي وجوهاً/موظفين. تُحفظ محلياً فقط ولا تُرفع إلى Git (مضبوط في `.gitignore`).

### اختبار الإضاءة
- صور بإضاءة طبيعية نهارية
- صور بإضاءة صناعية ليلية

- زاوية علوية (CCTV نموذجية)
- زاوية جانبية
- شخص يبتعد/يقترب من الكاميرا

- شخص واحد
- 2–3 أشخاص في الإطار
- ازدحام (4+ أشخاص متداخلين)

### اختبار ضبابية الحركة
- شخص ثابت
- شخص يتحرك بسرعة (تظهر ضبابية)

> غطِّ هذه الحالات داخل كل مجلد لتحصل على تقييم يعكس الواقع التشغيلي.

## 7. كيف تقرأ تقرير الدقة

لكل فئة مخالفة يُحسب جدول الالتباس (Confusion Matrix):

| المصطلح | المعنى |
|---------|--------|
| **TP** (إيجابي صحيح) | صورة مخالفة، والنموذج اكتشف المخالفة ✅ |
| **FN** (سلبي خاطئ) | صورة مخالفة، والنموذج **فاتته** ❌ (خطير) |
| **FP** (إيجابي خاطئ) | صورة سليمة، والنموذج أطلق **إنذاراً كاذباً** ⚠️ |
| **TN** (سلبي صحيح) | صورة سليمة، والنموذج لم يُنذر ✅ |

والمقاييس:

- **الدقة (Accuracy)** = (TP + TN) / الإجمالي → نسبة الصواب الكلية.
- **الدقة الإيجابية (Precision)** = TP / (TP + FP) → كم من الإنذارات كانت صحيحة (يقيس الإزعاج من الإنذارات الكاذبة).
- **الاستدعاء (Recall)** = TP / (TP + FN) → كم من المخالفات الحقيقية اكتُشفت (يقيس الأمان — المخالفات الفائتة).

> **للسلامة الغذائية:** الـ **Recall** غالباً أهم — مخالفة فائتة أخطر من إنذار كاذب.

## 8. عتبات الإنتاج (معايير الاجتياز)

| المخالفة | عتبة الدقة |
|----------|-----------|
| `no_mask` | ≥ 90% |
| `no_gloves` | ≥ 75% |
| `no_headcover` | ≥ 85% |
| `improper_uniform` | ≥ 80% |
| `wet_floor` | ≥ 80% |
| `trash_on_floor` | ≥ 80% |
| `unclean_area` | ≥ 80% |
| `blocked_path` | ≥ 80% |
| `unsafe_area` | ≥ 80% |

الفئة التي تتجاوز عتبتها → **اجتاز (Passed)**. أقل منها → **يحتاج إعادة تدريب (Needs retraining)**.

## 9. ماذا تفعل عند فشل فئة؟

عند ظهور **Needs retraining** لفئة:

1. **افحص نوع الخطأ السائد:**
   - **FN عالٍ (مخالفات فائتة):** النموذج لا يرى المخالفة → اجمع المزيد من صور المخالفة بزوايا/إضاءة متنوعة وأعد التدريب.
   - **FP عالٍ (إنذارات كاذبة):** النموذج حساس زيادة → اجمع المزيد من الصور السليمة، وارفع عتبة الثقة (`--conf`).
2. **راجع جودة الصور** في المجلد — صور غير واضحة أو مصنّفة خطأ تُفسد النتيجة.
3. **زِد عدد الصور** إلى 50+ لكل فئة لتقليل تأثير العينة الصغيرة.
4. **أعد التدريب** باستخدام أدوات `scripts/ppe_*` أو خط تدريب مخصص، ثم استبدل ملف `.pt`.
5. **أعد التشغيل** وقارن التقرير الجديد بالسابق.
6. لا تعتمد الفئة في الإنتاج حتى تتجاوز عتبتها.
